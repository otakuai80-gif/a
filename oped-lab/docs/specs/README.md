# 演出仕様書の読み方

OP/ED を3つのジャンルに分け、ジャンルごとにサンプル5本の仕様と、そこから作る試作1本の仕様をまとめています。

| ファイル | ジャンル | サンプルの根拠 | 試作 |
|---|---|---|---|
| [01-youtube.md](01-youtube.md) | YouTube系のOPとED | 公開テンプレートのコード(実測) | `YT-OP`、`YT-ED` |
| [02-anime.md](02-anime.md) | アニメ風のOP | 公開されている分析記事と論文(文献) | `ANIME-OP` |
| [03-broadcast-corporate.md](03-broadcast-corporate.md) | 番組・企業系のオープナー | 公開テンプレートのコード(実測) | `CORP-OPENER` |
| [_template.md](_template.md) | 新しいサンプル用の空の仕様書 | | |

## 根拠の種類

仕様書の数値には、どこから得たかを必ず書きます。

| 表記 | 意味 | 信頼度 |
|---|---|---|
| コード実測 | MIT ライセンスで公開されている Remotion テンプレートのソースから、フレーム数やばねの定数を読み取った | フレーム単位で正確 |
| 動画実測 | `scripts/analyze.sh` で動画ファイルを分析した | カットは正確、動きは目視で補う |
| 文献 | 公開されている分析記事や論文に書かれた数値と構造 | 記事の精度に依存。動画での確認はしていない |
| 目視 | 配信を見ながら手で記録した | 秒単位。フレーム精度はない |

現時点の状態:

- YouTube系と番組・企業系の10本は、すべて「コード実測」です。
- アニメ風の5本は、すべて「文献」です。この環境からは動画を視聴できないため、元の映像での確認はしていません。配信を見ながら `_template.md` を埋めるか、権利のある動画を `scripts/analyze.sh` にかけて「動画実測」か「目視」に置き換えてください。

## 再現判定の記号

| 記号 | 意味 |
|---|---|
| ◎ | Remotion の標準機能だけで再現できる |
| ○ | 追加パッケージか事前の解析が必要 |
| △ | 素材動画を重ねるなど、外部の素材に頼る |
| × | Remotion では作れない。完成した素材を合成するだけ |

## 時間の書き方

- 30fps、1920×1080 が基準です。`f30` は30フレーム目(1秒)を指します。
- 音楽に合わせるものは「小節.拍」でも書きます。`3.2` は3小節目の2拍目です(1始まり)。コード側の `cuts.ts` は0始まりなので1ずれます。
- ばねの動きは `spring(damping, stiffness, mass)` の値を書きます。書いていない値は Remotion の既定値(damping 10、stiffness 100、mass 1)です。
- イージングの名前(out、in、inOut、back)は `src/lib/anim.ts` の `EASE` と対応します。

## 扱いの原則

サンプルから取り入れるのは、構成、尺、タイミング、動きの種類といった技法だけです。題名、ロゴ、キャラクター、楽曲、歌詞などの素材は使わず、試作ではすべて新しく作ります。
